このページでできること

銀行やカード会社から保存したCSVを読み、日付・摘要・金額の3列へ整えます。たとえば、日付の「R8.1.5」を「2026-01-05」へ、金額の「△１，２３０円」を「-1230」へ変換します。出金列と入金列が別々の明細も、出金をマイナス、入金をプラスにまとめます。

変換例: R8.1.5 / 文具購入 / △１，２３０円 → 2026-01-05 / 文具購入 / -1230

文字コード、見出し行、列の割り当て、金額の持ち方は結果画面に表示します。自動判定を確認したうえで保存でき、元のCSV自体は変更しません。

ファイルはどこにも送信されません

変換処理は、このページを開いているブラウザの中だけで完了します。サーバーへ明細を送る通信コードやアクセス解析、外部フォント、外部配信の部品は使っていません。

さらにContent Security Policy（CSP）で外部接続を禁止しています。HTML・CSS・JavaScriptのソースも公開ファイルとして確認できるため、「送信しない」という説明と実装を照らし合わせられます。

よくある詰まりどころ

明細を開くと文字化けする

CSVには主にShift_JISとUTF-8があり、開くソフトとの組み合わせで文字化けします。このツールは両方を判定して読み、変換後はExcelで開きやすいUTF-8（BOM付き）で保存します。

日付が会計ソフトに弾かれる

「R8.1.5」や「令和8年1月5日」、「20260105」を西暦の「2026-01-05」に統一します。存在しない日付は推測で直さず、読めなかった行として表示します。

△や全角数字が数値にならない

「△440」「１，２００円」などを符号付きの整数へ整えます。小数や文字が混じる値は勝手に丸めず、確認が必要な行として分けます。

出金と入金が別の列にある

銀行明細に多い出金・入金の2列を1つの金額列へまとめます。出金はマイナス、入金はプラスになり、サマリでもそれぞれの合計を確認できます。

口座情報の行で見出しがずれる

先頭だけを見出しと決めつけず、最初の20行から日付と金額の列がある行を探します。判定した見出しの行番号と列名を結果に表示します。

よくある質問

明細ファイルはどこかに送信されますか？

送信しません。読み込みと変換とダウンロードはすべて利用中のブラウザ内で完結します。アクセス解析や外部配信のライブラリも使っておらず、Content Security Policy で外部接続そのものを禁止しています。

和暦の日付も変換できますか？

できます。R8.1.5、令和8年1月5日、H31.4.30、20260105 などを西暦の YYYY-MM-DD に統一します。存在しない日付は推測で直さず、読めなかった行として表示します。

金額の △ や全角数字はどうなりますか？

△440 は -440 に、全角の１，２００円 は 1200 になります。小数や文字が混じる値は勝手に丸めず、確認が必要な行として分けます。

出金と入金が別々の列に分かれている明細も扱えますか？

扱えます。出金をマイナス、入金をプラスとして1つの金額列にまとめます。どの列を何と判定したかは結果画面に表示されます。

freeeや弥生、マネーフォワードに取り込めますか？

このツールが出すのは日付・摘要・金額の3列のCSVです。多くの会計ソフトはこの3つを含むCSVを取り込めますが、列の順序や見出しの名前は各ソフトの取込画面で対応づける必要があります。特定のソフトへの取り込みを保証するものではなく、各社との提携もありません。取り込む前に行数と入出金の合計を元の明細と照合してください。

PDFやExcelの明細は変換できますか？

対応していません。CSV形式の明細をご用意ください。

対応していないこと

PDF、Excel（.xlsx）ファイルの変換、金融機関からの明細の自動取得、勘定科目や税区分などの税務判断には対応していません。CSV形式の明細を用意してから利用してください。

免責

自動判定や変換結果が、すべての金融機関・会計ソフトの形式に合うことを保証するものではありません。取り込む前に、元の明細と行数・期間・入出金合計を照合し、利用者の責任で内容を確認してください。
